WHAT WE FIXED / BUILT
-----------------------

1. COACH AUTH — SWITCHED FROM COOKIES TO SESSIONSTORAGE + HEADER
   Root cause: the Worker (ctt-worker.andermd535.workers.dev) and Pages
   (ctt-academy.pages.dev) are on different domains. Chrome and Safari block
   cross-site cookies even with SameSite=None, so the session cookie set by
   the Worker after OAuth was never sent back on subsequent requests — coach
   pages appeared to load then immediately redirect to the landing page.

   New flow:
   - After GitHub OAuth, the Worker redirects to:
       dashboard.html#session=TOKEN
     (URL fragment — never sent to any server, not in browser history)
   - auth.js captures the token from the hash on page load, stores it in
     sessionStorage as 'ctt_coach_token', and strips the hash from the URL
   - All coach API requests now send: X-Coach-Token: TOKEN (header)
   - Worker validates the X-Coach-Token header instead of a cookie
   - Logout sends X-Coach-Token to the Worker to delete the KV record,
     then clears sessionStorage

   Security tradeoff documented in CLAUDE.md: sessionStorage is readable by
   JS (unlike HttpOnly cookies), but the strict CSP mitigates XSS. This
   approach is CSRF-immune. Revisit when a custom domain is set up.

   Files changed: worker/index.js, js/auth.js, js/api.js

2. MULTI-COACH SUPPORT — OWNER_GITHUB_ID NOW COMMA-SEPARATED
   Previously only one GitHub user ID could be the coach. Updated the Worker
   to split OWNER_GITHUB_ID on commas and check against the full list.
   Cooper's numeric GitHub user ID was added to the secret:
     wrangler secret put OWNER_GITHUB_ID
     value: 283034047,COOPERS_ID
   Both Mitch and Cooper can now log in as coach independently.
   No redeploy needed — Worker secrets take effect immediately.

   Files changed: worker/index.js

3. SESSION.HTML — FIXED ENDLESS SPINNER
   session.js references document.getElementById('nav-back-link') to render
   a "← Player" back link, but the element didn't exist in session.html.
   The JS threw a TypeError silently, execution stopped, and the page was
   stuck showing the default spinner forever. This bug was pre-existing but
   only discoverable after auth was working (nobody could reach session.html
   before the auth fix above).
   Fixed by adding <div id="nav-back-link"> to session.html.

   Files changed: session.html

PLAYER FLOW
-----------
1. Player visits ctt-academy.pages.dev
2. Enters their email address → clicks "Access My Profile"
3. If found: goes straight to their profile page (read-only)
4. If multiple profiles found (parent with kids): sees a selector screen to pick
   which player to view
5. If not found: offered to create a profile
6. Registration requires: first name, last name, email, phone (all required —
   hard stop if any are missing). Optional: NTRP level, improvement goals,
   parent/guardian email
7. Parent email: if provided, that parent email also gets access to this player's
   profile. A parent with two registered kids sees both profiles on login.
8. Session data stored in browser sessionStorage — clears when tab closes
   (intentional — appropriate for shared devices)

KV DATA SCHEMA
--------------
player:{playerId}             Full player object
email-index:{email}           Array of playerIds linked to that email
lttdp:{playerId}              LTTDP object (4 sections)
sessions:list:{playerId}      Ordered array of session IDs (newest first)
session:{sessionId}           Individual session object
players:all                   Array of all player IDs (for dashboard)
owner:session:{token}         Coach session (32-byte random token, 7-day TTL)
oauth:state:{state}           CSRF protection for OAuth flow (10-min TTL)

All player IDs and session IDs are UUID v4 (not sequential — not guessable).
Email keys are always lowercased and trimmed before read/write.

SECURITY DECISIONS MADE
------------------------
- Email-only player auth: intentional tradeoff. Anyone with a player's email
  can see their profile. Acceptable because data is coaching notes only — no
  financial, medical, or sensitive personal information.
- Coach auth via GitHub OAuth: more secure than a PIN (PIN is brute-forceable;
  GitHub OAuth is not). The /coach URL is hidden — not linked from anywhere on
  the site. Finding the URL alone doesn't grant access.
- sessionStorage for player sessions: clears on tab close. Appropriate for
  shared devices (a parent at a front desk).
- No secrets in any source file — all via wrangler secret put.
- CORS locked to ctt-academy.pages.dev and cooperteachestennis.github.io only.
- CSP headers on all Worker responses. No inline scripts anywhere in HTML.
